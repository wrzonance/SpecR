# Design: Copy-on-Derive — Project Sections Become Owned Copies (#94)

**Date:** 2026-06-11
**Issue:** #94 — feat(db): copy-on-derive — project sections become owned copies via project_sources resolution
**ADR basis:** ADR-015 D2 (copy-on-derive with drift visibility) and D3 (multi-source project resolution)
**Depends on (merged before implementation starts):** #92 (libraries table, `specs.library_id XOR specs.project_id`, partial unique indexes), #93 (`parent_spec_id`, `origin_version`, `content_version`, `origin_meta` on specs)

## Problem

`addSpecToProject` aliases the shared library row: a `project_specs` join row points at the
same spec every other project sees. Editing a "project" section mutates the master. Projects
must own copies, and project creation must accept an ordered source list with per-section
fallback (client master missing a section falls through to the company master).

## Decisions made during brainstorm

| # | Question | Decision |
|---|----------|----------|
| 1 | Add-section API shape | **Section number only.** `POST /projects/:id/specs` body becomes `{ section }`; resolution always walks `project_sources` priority. Explicit per-section source override is a follow-up issue, not built now. |
| 2 | Which tiers may be project sources | **Company + client only** (strict ADR-015 D3 reading). Reference-tier (UFGS) content must first be derived into a company master. Enforced at the query layer (cross-table CHECK would need a trigger). Lineage edges (`parent_spec_id`) are NOT tier-restricted — backfilled clones may point at reference rows they actually aliased. |
| 3 | Removing a section from the TOC | **Block removal if edited.** Clean clones (`content_version = 1`) delete freely (join row + refs + clone + paragraph tree). Edited clones (`content_version > 1`) → 409 unless `?force=true`. |
| 4 | Paragraph-grain lineage | **Store `origin_paragraph_id`.** Nullable UUID on `paragraphs`, FK → `paragraphs(id)` ON DELETE SET NULL, populated only at clone time. Preserves the paragraph mapping the future re-pull/rebase command needs (Phase 3 diff matches by UUID); cannot be backfilled later if skipped. |
| 5 | Clone implementation | **SQL set-based clone in a single transaction** (Approach A). Never round-trips through `getSpecTree`/`buildTree`, which drops empty paragraphs and would make the clone lossy. |

## Schema

Two migrations (numbered sequentially after whatever #92/#93 land as).

### Migration A — `project_sources` + paragraph lineage

```sql
CREATE TABLE project_sources (
  project_id  UUID NOT NULL REFERENCES projects(id) ON DELETE CASCADE,
  library_id  UUID NOT NULL REFERENCES libraries(id),
  priority    INTEGER NOT NULL CHECK (priority >= 1),
  PRIMARY KEY (project_id, library_id),
  UNIQUE (project_id, priority)
);

ALTER TABLE paragraphs ADD COLUMN origin_paragraph_id UUID
  REFERENCES paragraphs(id) ON DELETE SET NULL;
CREATE INDEX paragraphs_origin_idx ON paragraphs (origin_paragraph_id)
  WHERE origin_paragraph_id IS NOT NULL;
```

- Tier restriction (company|client) is validated in `createProject` at the query layer;
  the migration documents this in a comment.
- Down: drop index, drop column, drop table.

### Migration B — backfill aliased projects

1. Every existing project gets `project_sources = [(Default Company Master, priority 1)]`.
   (`Default Company Master` is created by #92's backfill.) This governs *future*
   resolution only.
2. Every `project_specs` row whose spec is library-owned (`library_id IS NOT NULL`) is
   cloned into a project-owned copy using the same SQL clone pattern as runtime:
   - clone spec row: `project_id` set, `library_id` NULL, `parent_spec_id` = master id,
     `origin_version` = master `content_version`, `content_version` = 1, `origin_meta`
     copied;
   - clone paragraph tree with UUID map, `origin_paragraph_id` recorded;
   - clone outgoing `spec_references` with remapped source ids; targets re-resolved
     within the project after all of that project's clones exist (two-pass);
   - `project_specs.spec_id` repointed to the clone (position preserved).
3. Down: repoint `project_specs.spec_id` back to `parent_spec_id`, delete clones (their
   paragraphs/refs cascade). Post-migration edits to clones are lost on down — documented
   and accepted.

## API contracts (`openapi.yaml` updated)

### `POST /projects`

Body: `{ name, description?, sourceLibraryIds: UUID[] }`.

- `sourceLibraryIds` **required, min 1**, no duplicates. Each must exist and have tier
  `company` or `client`, else 422. Priority = array order (1-based).
- Required because section-resolution is the only way to add specs — a sourceless project
  would be a dead end.
- Response includes `sources`.

### `GET /projects/:id`

Response gains `sources: [{ libraryId, name, tier, priority }]`.

### `POST /projects/:id/specs`

Body: `{ section }` — validated against the expanded section-number grammar
(`lib/section-number.ts`).

- Resolution: walk `project_sources` by priority; first library holding a master spec with
  that section wins → clone. Other sources also holding it become the advisory.
- Response: `{ specId, section, position, source: { libraryId, name }, shadowed?: [{ libraryId, name }] }`
  where `specId` is the **clone's** id.
- No source holds the section → 422. Section already in the project → 409
  (`UNIQUE (section, project_id)`).

### `DELETE /projects/:id/specs/:specId` (+ `?force=true`)

- Spec must be owned by this project (404 otherwise).
- `content_version > 1` without `force` → 409 with explanatory message.
- Otherwise delete atomically: ref rows, join row, clone spec + paragraph tree.
- Existing broken-ref marking for other project specs that referenced it is preserved.

## Clone + cross-reference semantics (`src/db/queries/derive.ts`)

New file — keeps `projects.ts` (217 lines) under the 400-line budget. All steps in **one
transaction** on a dedicated client (`pool.connect()`):

1. **Resolve** per section through `project_sources` priority; collect shadowed sources.
2. **Clone spec row**: new UUID; `project_id` set; `library_id` NULL;
   `parent_spec_id` = master; `origin_version` = master's `content_version`;
   `content_version` = 1; `origin_meta` copied from the master (file provenance stays true).
3. **Clone paragraphs**: single `INSERT … SELECT` with a UUID-map CTE
   (`old_id → gen_random_uuid()`); `parent_id` remapped via self-join on the map;
   `origin_paragraph_id` = source paragraph id. Lossless by construction — no tree
   reconstruction.
4. **Clone outgoing refs**: `source_spec_id`/`source_paragraph_id` remapped via the map.
   Target resolution is **project-scope first**: target section already among this
   project's specs → `target_spec_id` points at that clone, `is_broken = false`; otherwise
   `target_spec_id` NULL, `is_broken = true`, `target_spec_section` retained (the existing
   repair CTE in `addSpecToProject` fixes these when the section is later added).
   Intra-spec `target_paragraph_id` remapped via the map; cross-spec paragraph targets set
   NULL (cannot be mapped into another spec's clone).
5. **TOC row** (`project_specs`, position = max+1) + existing project-scoped broken-ref
   repair.

### "Then source libraries"

A project ref never silently points outside the project. Instead, `getBrokenRefs` is
annotated: each broken ref gains `availableFrom: [{ libraryId, name }]` — the project's
source libraries that hold the missing target section — turning the broken-ref report into
an actionable "add this section" prompt.

## Testing

Integration (real PostgreSQL):

- Clone is lossless: paragraph row count, text, node types, parent/position structure,
  `conflicts` JSONB all equal the master's — compared via SQL, **not** via `buildTree`.
- All clone paragraph UUIDs are new; `origin_paragraph_id` mapping is complete.
- **Headline regression:** editing the project copy leaves the master untouched.
- Fallback: section absent from client master (priority 1) resolves from company master
  (priority 2).
- Shadow advisory: section present in both sources → advisory lists the shadowed library.
- No source holds section → 422; duplicate section in project → 409.
- Removal guard: edited clone → 409; `force=true` deletes; clean clone deletes freely.
- Backfill migration up/down on a seeded aliased project.
- Ref behavior: intra-project ref repaired on add; master's refs untouched by clone edits.
- `POST /projects` rejects reference-tier and unknown libraries (422).

Unit: Zod request schemas; resolution-ordering logic if extracted as a pure function.

- Per-section explicit source override.
- Library→library derivation (client master from company master).
